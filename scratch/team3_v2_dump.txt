P4: 1)Problem Statement :-
P5: In many colleges, academic timetables and resource allocation are still managed manually, making it difficult to handle sudden changes, additional classes, and faculty unavailability. These challenges often result in scheduling conflicts, underutilized classrooms and laboratories, and uneven faculty workloads. Managing multiple scheduling requests is also complicated due to the lack of a systematic approach to prioritizing requests, ensuring fairness, and considering resource availability. Therefore, an efficient system is needed to simplify timetable management, optimize the use of existing resources, and ensure smooth academic activities with minimal disruption.

P23: i)E1 - Scheduling & Concurrency Controller(Operating Systems):-
P24: 1. What it does
P25: Handles multiple booking requests at the same time and makes sure that two people don't get the same resource simultaneously.
P26: Maintains three queues: READY, WAITING and RETRY. If a request cannot be processed immediately, it is placed in a queue and handled in order.
P27: Uses priority rules to decide which request should be processed first.
P28: Protects shared data using locks and critical sections so that multiple requests don't create conflicts or incorrect results.
P31: 2. What students should do
P32: - Define the complete journey of every request:
P33: NEW → VALIDATED → READY → RUNNING → ALLOCATED / WAITING / REJECTED
P34: Implement a priority system where important requests are processed first. If two requests have the same priority, process the one that arrived earlier.
P35: Use locks to protect important operations, especially when checking and booking a resource.
P36: Test multiple requests trying to book the same resource at the same time. Make sure only one request gets the resource.
P37: Measure system performance using:
P38: Average and maximum waiting time.
P39: Time spent waiting for locks.
P40: Number of requests waiting for too long (starvation).
P41: Number of deadlock events (target: zero).

P115: 8)Workflow:-
P116: The Smart Campus Lab & Resource Optimizer begins when a Faculty member or HOD logs into the system, where the system authenticates their credentials, identifies their role and provides access to the appropriate dashboard. The authorized user can then search for available resources or submit a resource request by specifying the activity, required time slot, group size and other requirements. The system validates the request and retrieves the available resource information, timetable data, faculty availability and configured rules. It then filters the resources in a specific order: time availability, capacity, resource type and suitability, facilities and department-sharing rules, and faculty availability. If suitable resources are found, the system ranks them according to configured weights and suitability, and proceeds with the allocation process. Before confirming the allocation, it checks the latest booking information to ensure that no other request has occupied the same resource during that time. If all constraints are satisfied, the system allocates the resource, updates the request status and records the allocation details. If multiple requests compete for the same resource, the system applies the configured priority and authority rules to resolve the conflict and supports authorized reallocation where necessary. If no suitable resource is available, the system identifies the reason, searches for feasible alternative resources and presents them to the requester. The requester can accept an alternative, reject it and choose to join the waiting queue, or leave the request unresolved. Whenever a resource becomes available, the system re-evaluates eligible queued requests and attempts allocation again. Throughout the process, the system handles validation errors and transaction failures without affecting previously confirmed allocations, while maintaining records of requests, decisions, actions and outcomes. Finally, the HOD and Administrator can access dashboards to monitor faculty workload, allocation fairness, resource utilization, department-wise usage, parameter comparisons and audit history.
